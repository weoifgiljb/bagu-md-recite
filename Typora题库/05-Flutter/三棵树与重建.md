# 题：Widget / Element / RenderObject 三棵树与重建？

## 面试官可能怎么问

- 三棵树各负责什么？
- setState 后发生了什么？什么叫重建？
- key 在复用 Element 时起什么作用？

## 口述结构（90 秒）

1. Widget 配置（不可变）；Element 实例生命周期；RenderObject 布局绘制
2. setState → 标记脏 → build 新 Widget 子树 → Element reconcile
3. 同 runtimeType+key 可更新复用；否则卸挂重建
4. 控制 rebuild 范围：拆 widget、const、状态下沉/提升得当

## 参考答案

### 对应问 1：三棵树职责

| 树 | 本质 | 职责 |
| --- | --- | --- |
| **Widget** | 不可变配置/描述 | 告诉框架「想要什么 UI」 |
| **Element** | 可变实例，连接两棵树 | 生命周期、持有 State、执行 build、reconcile |
| **RenderObject** | 布局与绘制 | 约束传递、size、paint、命中测试 |

口诀：**Widget 配置，Element 管理，Render 真干活。**

### 对应问 2：setState 后发生什么

步骤：
1. `setState` → 对应 Element 标脏
2. 帧末调度 build：`State.build` 返回**新的 Widget 子树**
3. Element 与新 Widget **reconcile（diff）**
4. 能复用则 `update`；不能则卸载旧 Element/RenderObject，挂载新的
5. RenderObject 重新 layout/paint（若布局信息变）

**重建（rebuild）**：主要指重新 `build` 出 Widget，**不等于**每次都销毁 Element。优化目标是：少标脏、缩小 build 范围、提高复用。

### 对应问 3：key 的作用

reconcile 时大致看：`runtimeType` + `key` 是否匹配。

- 列表重排/插入：给稳定业务 id 作 `ValueKey`/`ObjectKey`，避免「错位复用」导致状态串台
- 无 key：按位置对齐，重排时 State 可能留在错误的 item 上

步骤（列表）：
1. `ListView.builder` + 稳定 key
2. 数据换序时 Element/State 跟着 id 走
3. 不要用 `index` 当 key（除非列表静态）

**业务例子**：聊天列表气泡用消息 id 作 key；主题切换时大片 rebuild，用 `const` 与拆分缩小范围。
