# 题 3：H5 和微信小程序差在哪？Taro 多端要注意什么？

## 面试官可能怎么问

- 小程序是双线程模型，和浏览器单页有何不同？
- DOM/BOM、路由、存储、网络分别有哪些限制？
- Taro 写一套跑 H5 + 小程序，常见坑是什么？

## 口述结构（90 秒）

1. 先讲运行时：逻辑层 JS + 视图层，无完整 DOM
2. 再讲能力：域名白名单、包体积、组件标签、API 差异
3. Taro 用 React/Vue 语法编译到各端，条件编译补差异
4. 业务上 AI 流式、富文本、登录在两端策略不同

## 参考答案

### 1. 运行时差异（核心）

| 维度 | H5 / 浏览器 | 微信小程序 |
| --- | --- | --- |
| 文档模型 | 完整 DOM/BOM | 无 DOM；WXML 组件树 |
| 线程 | 大致单页 JS + 渲染 | 逻辑层与视图层分离，经桥通信 |
| 路由 | History/Hash、任意 SPA | 页面栈 + tabBar，API 受限 |
| 网络 | fetch/XHR，受 CORS | request 合法域名；非 CORS |
| 包体 | 按需加载灵活 | 主包/分包大小硬限制 |
| 安全 | CSP/XSS 主战场 | 封闭生态 + 域名与权限 |

小程序里「改数据 → 视图更新」依赖 setData 通信；不能假设 `document.querySelector`。Taro 会把部分 DOM 操作编译/抹平，但**触及真实 DOM 的库**（很多编辑器、图表）在小程序端要换实现或降级。

### 2. 能力与审核限制（步骤口述）

1. **网络**：后台配置 request/upload/download/socket 合法域名；必须 HTTPS。  
2. **登录**：`wx.login` → code 换 session；不是随便 OAuth 弹窗。  
3. **UI**：用小程序组件 / Taro 组件；CSS 子集（注意 rpx、部分选择器限制）。  
4. **支付/分享/订阅消息**：走平台 API 与类目权限。  
5. **包体积**：主包超限必须分包；图片进 CDN。

### 3. Taro 多端注意点

```ts
// 条件编译示例
if (process.env.TARO_ENV === 'h5') {
  // EventSource / 完整 Markdown 预览
} else {
  // 非流式 + 轻量富文本
}
```

落地建议：

1. **UI 用 Taro 组件**，少直接操作 DOM。  
2. **网络走自封装 request**，H5 可走代理，小程序走域名白名单。  
3. **路由**：`Taro.navigateTo` / `switchTab`；tab 页不能 navigateTo 进 tab。  
4. **AI**：H5 可 SSE；小程序优先非流式或 WS，假打字机控 setData。  
5. **真机验收**：域名、权限、性能以真机为准。

**业务例子**：同一 Nest AI 契约，Web 用 SSE 打字机；Taro 小程序用 request + 气泡状态机；富文本用轻量着色而非完整 DOMPurify 浏览器方案硬搬。

## 可能追问

- 能在小程序里跑完整 React DOM 吗？→ 不是浏览器 DOM；是 Taro 运行时映射。
- Skyline / 新渲染引擎？→ 知道「性能与兼容在演进」，项目以实际基础库为准。
- uni-app 对比？→ 都是多端；面试抓住「抹平成本 vs 原生能力」即可。
