# 题 5：小程序登录怎么做？Token 存在哪？和 H5 有何不同？

## 面试官可能怎么问

- wx.login 的 code 换 session 流程？
- Token 放 Storage 还是内存？怎么刷新？
- 静默登录失败、401 怎么统一处理？

## 口述结构（90 秒）

1. wx.login → code → 服务端换 openid/session → 下发自有 Token
2. 请求头带 Token；合法域名 HTTPS
3. 本地可存 refresh/access；敏感操作二次校验
4. 401 清态并引导登录；与 Web 共用用户体系时对齐字段

## 参考答案

### 1. 标准登录步骤

1. 前端 `wx.login` / `Taro.login` 拿到 **短期 code**（不是最终用户凭证）。  
2. 把 code 发给自家后端；后端用 appId/secret 向微信换 `openid`/`session_key`。  
3. 后端建立/查找用户，签发 **业务 Token**（JWT 或 session id）。  
4. 前端存 Token，后续 `Authorization: Bearer ...` 调业务 API。  
5. 需要手机号/头像等，走按钮组件授权或新隐私接口——与「静默登录」分开讲。

```ts
async function ensureLogin() {
  const { code } = await Taro.login()
  const { token, user } = await api.post('/auth/wx', { code })
  await Taro.setStorage({ key: 'access_token', data: token })
  return user
}
```

### 2. 存储与安全口径

- **access_token**：可放 `Storage`；小程序无 HttpOnly Cookie 那套浏览器模型。  
- **session_key**：只留在服务端，**绝不下发前端**。  
- 加密敏感字段、最短权限；退出登录 `removeStorage` + 内存态清空。  
- 刷新：access 短过期 + refresh，或 401 时静默 `wx.login` 再换票（注意频控）。

### 3. 和 H5 差异 & 统一踢登

| | 小程序 | H5 |
| --- | --- | --- |
| 身份入口 | wx.login code | 密码/短信/OAuth |
| 凭证携带 | Header 为主 | Cookie 或 Bearer |
| CSRF | 弱相关（非自动 Cookie） | SameSite/Token 重要 |

统一请求封装：识别 401 → 清 Token → `reLaunch` 到登录/我的页 → 可选静默重登一次，失败再打断用户。

**业务例子**：审评小程序 Demo Token 与正式 wx 登录可切换；AI 与文档 API 共用同一 auth header。

### 4. 完整时序（可画在纸上）

1. 冷启动 `App.onLaunch` → 读 Storage 里 Token。  
2. 有 Token → 调 `/me` 探活；401 则清掉并走静默登录。  
3. 无 Token → `Taro.login` 取 code → `POST /auth/wx` → 存 Token + 用户资料。  
4. 业务请求统一带头；并行请求若同时 401，只触发一次踢登（加锁/标志位）。  
5. 用户主动退出：清 Storage、清内存 store、`reLaunch` 到未登录态页面。  

**风控补充**：同一 code 只能用一次；服务端校验 `appId`；刷票接口限流。Demo 环境可用固定 Demo Token，但面试要声明「与正式 wx 登录分支隔离，避免讲成生产方案」。

**和 H5 单点登录**：后端发同一用户体系的 access/refresh；小程序端没有浏览器 Cookie 自动携带，所有端都显式 Header，反而更容易统一 CSRF 口径。

## 可能追问

- getUserProfile 还能用吗？→ 策略多变，面试强调「头像昵称与登录解耦、按最新文档」。
- 多端同一账号？→ 后端用 unionId/绑定表打通，前端只持业务 Token。
- Token 被盗怎么办？→ 短过期、刷新轮转、异地失效；传输必须 HTTPS。
