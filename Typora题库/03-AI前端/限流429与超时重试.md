# 题 17：限流/429/额度用尽/模型超时的前端文案与重试？

## 面试官可能怎么问

- 429 和额度用尽文案如何区分？
- 重试策略怎么设计？

## 先自己答（90 秒）

## 参考答

**分类提示**
- **429 限流**：请求太频繁 → 「请稍后再试」+ 倒计时（读 `Retry-After` 若有）
- **额度用尽**：账单/配额问题 → 「额度已用完，请联系管理员/明天再试」，不要盲目重试打爆
- **模型超时 / 504 / 网关超时**： 「生成超时，可重试或缩短问题」
- **取消**：不提示失败，标记已停止

**重试策略**
- 指数退避 + 抖动；设最大次数（如 2–3）
- 幂等：同一 `clientMessageId`；UI 只留一条消息
- 用户可手动「重试」；自动重试要可取消
- 额度类错误：**自动重试关闭**

**体验**：保留输入框内容；错误气泡可点重试；全局 toast 不代替行内错误。

**业务例子**：演示环境 Demo Token 也可能限流；文案区分「令牌无效」与「限流」。

## 可能追问

- 和 Abort 关系？→ 重试前确认未 abort。
