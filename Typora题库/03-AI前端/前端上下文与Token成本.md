# 题 4：对话上下文很长时，前端要管什么？

## 面试官可能怎么问

- 为什么不能每次把全部历史原样塞给模型？
- 前端如何展示「上下文已截断」？
- 多模态（图/文件）怎么进上下文？
- 你怎么和成本/限流策略配合？

## 参考答

**原则**：上下文窗口有限且按 token 计费；前端负责**可见历史**，真正裁剪策略多在后端，但前端要协同。

**前端职责**
- 展示：哪些消息会进入下一轮（灰显被摘要/裁掉的部分）
- 发送：带 `conversationId`，不要每次自己拼超长 prompt（除非本地小模型）
- 附件：上传后传 `fileId`，不要反复 base64 塞进消息
- 限流：429/额度用尽时的可理解提示与重试退避

**常见策略（懂概念即可）**
- 滑动窗口：只留最近 N 轮
- 摘要：旧对话压缩成 summary message
- 检索：相关片段才进 prompt（和 RAG 衔接）

**业务例子**：客服 bot 聊了 40 轮后答非所问——可能是早期关键信息被裁掉；产品上要提示「长期记忆/摘要」或让用户固定关键资料。
