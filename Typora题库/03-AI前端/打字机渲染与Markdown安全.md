## 参考答

**目标**：看起来像打字机，但不把主线程打满，且不给 XSS 机会。

**渲染策略**
- 消息维度更新：只更新当前 streaming 那一条，不要重渲染整个历史列表
- 节流：如 50–100ms 合并一次 UI 更新，或按「完整字符/词」更新
- 列表虚拟化：历史很长时用虚拟列表（只挂载可视区）

**Markdown**
- 流式中：可以先纯文本；或用支持增量的 markdown 管线；注意未闭合代码围栏
- 结束后：再做一次完整 markdown + 高亮
- **安全**：用户/模型内容都当不可信。用经过消毒的渲染（如 DOMPurify + 白名单标签），不要直接 `innerHTML` 原始模型输出

**业务例子**：回答里出现 ` ```html ` 或链接、图片时，既要能展示，又要禁用 `javascript:` 链接和 `onerror` 图片。

## 可能追问

- React 里怎么避免列表闪烁？→ 稳定 `key`（消息 id），streaming 消息用同一 id 更新
- 数学公式/Mermaid 何时渲染？→ 通常等流结束，避免半截语法爆红
