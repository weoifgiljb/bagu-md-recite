- conversationId 何时创建、如何持久化？

## 参考答

**状态分层**
- **会话级（可 Pinia/全局）**：当前 `conversationId`、会话列表、发送中锁、鉴权 token 句柄
- **消息级（会话内）**：`messages[]`（id、role、content、status: sending|streaming|done|error|stopped）
- **UI 级（组件内）**：输入框草稿、是否贴底、面板开关

**乐观更新**
1. 用户点发送 → 立刻插入 user 消息（`clientMessageId`）+ assistant 占位
2. 请求成功 → 用服务端 id/内容补丁；失败 → 标记错误、保留输入可重试，必要时回滚占位

**conversationId**
- 首条成功后由后端返回并写入 store；后续请求带上
- 刷新后从 URL / 本地存储 / 再拉会话详情恢复，不依赖内存

**Vue3 Pinia vs React**
- 思想相同：单一消息模型 + reducer/actions；框架只是壳
- 避免把「整棵 messages」深拷贝到每个气泡；用 id 订阅或 memo

**业务例子**：简历 Vue3+Pinia 站与 Taro React 小程序可共享同一套消息模型类型定义（即便运行时双栈）。
