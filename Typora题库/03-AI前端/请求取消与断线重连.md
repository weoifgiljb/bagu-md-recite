# 题 3：用户点停止、刷新页面、网络闪断，你怎么设计？

## 面试官可能怎么问

- 点「停止生成」前端做了什么？后端知道吗？
- `AbortController` 用在哪？
- 断线后是重连同一条流，还是新开请求？
- 如何避免重复追加内容？

## 先自己答（90 秒）

## 参考答

**停止生成**
- 前端：`AbortController.abort()` 取消 fetch；UI 立刻结束 streaming 状态
- 同时最好通知后端取消（若有 jobId），否则后端还在烧 token
- 本地保留已生成前缀，标记为 `stopped`

**刷新 / 离开页**
- `beforeunload` 不一定可靠；关键是服务端会话可恢复：用 `conversationId` + 已落库片段
- 回页后拉消息列表，不靠内存里的 stream

**闪断重连**
- SSE 有 Last-Event-ID 语义；很多业务用「消息 id + 已收到 offset/字符序号」续传
- 更稳妥：断了就停，提供「继续生成」按钮，把已有前缀当 context 再请求（注意重复）
- 幂等：同一 `clientMessageId` 重试不重复插入 user 消息

**业务例子**：用户在地铁上信号差，生成到一半白屏回来——应看到已生成部分 + 可继续，而不是空白或重复两段话。
