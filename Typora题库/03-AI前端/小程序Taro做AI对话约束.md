# 题 9：小程序 / Taro 做 AI 对话有哪些约束？

## 面试官可能怎么问

- 为什么小程序里不能随便上 SSE？
- setData 频率、包体积、域名校验分别怎么影响 AI 页？
- Taro 里对话列表怎么更新更稳？

## 先自己答（90 秒）

## 参考答

**核心差异**：小程序不是完整浏览器；网络、DOM、包大小都被平台卡死。

**网络**
- 请求必须走**合法域名**（微信后台配置 https）；本地联调要开不校验或用开发工具。
- **SSE / EventSource** 基本不可用或极受限；长连接多靠 **WebSocket**（也要配域名）或继续用 **Taro.request 非流式**。
- 流式若要做：常见是后端分片 + 短轮询，或自建网关转 WebSocket；成本高，演示期可非流式 + 假打字机。

**setData**
- 每次 setData 有序列化与通信开销；流式/假打字机若每字 setData 会卡。
- 策略：合并更新（50–100ms）、只更新当前消息字段、列表过长做分页/虚拟化（或只保留最近 N 条在视图层）。

**包大小**
- Markdown/高亮/DOMPurify 全量进主包容易超；按需分包、AI Tab 独立分包、富文本用轻量方案（如受限 HTML + `tintRichHtml` 思路）。

**业务挂载（doc-review-taro）**：AI Tab + ChatWidgets；文档列表/筛选；富文本着色。面试强调「先非流式契约跑通，再评估 WS/分片」。
