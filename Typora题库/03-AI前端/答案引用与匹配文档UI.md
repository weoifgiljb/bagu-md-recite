# 题 10：「答案带引用 / 匹配文档」的 UI 怎么做？

## 面试官可能怎么问

- 后端返回 matches 时，前端如何展示与跳转？
- 无匹配时要不要硬答？文案怎么写？
- 和 RAG「答案必须可追溯」怎么对齐？

## 先自己答（90 秒）

## 参考答

**信息架构**
- 主区：assistant `reply`
- 侧栏/底部/折叠区：`matches` 列表（标题、摘要、分数/来源标签）
- 交互：点击 match → 打开文档详情（带 `docId` / 锚点）；可选高亮命中片段

**有匹配**
- 回复中可用角标 `[1]` 与列表序号对应（若后端未给 span，先做列表级引用，不强行伪造段落高亮）
- 空 match 字段要兜底：`matches ?? []`

**无匹配**
- 产品策略二选一（面试说清取舍）：
  1. **拒答/弱答**：「未在文档库找到依据，请换个问法或先上传文档」
  2. **通识回答 + 警告条**：标明「非基于当前文档库」
- 审阅助手更偏向 1，避免胡编政策/条款

**状态**：`pending`（检索中）→ `searchMatches` 展示 → 用户打开文档。列表可与会话解耦缓存。

**业务例子**：`{ reply, matches }` 一次返回；先渲染 matches 骨架再填 reply，用户能立刻点进相关 Doc。

## 可能追问

- 点击后如何回到对话？→ 保留 conversation 栈或半屏文档。
