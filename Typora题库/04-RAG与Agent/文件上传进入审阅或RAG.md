## 参考答

**典型流水线**
1. 选择文件 → 校验类型/大小
2. 直传或直传凭证（`POST` 拿 uploadUrl）→ 展示进度
3. 完成得 `fileId` / 创建 `Doc` 记录
4. 后端解析/入库/建索引（状态：`uploading|processing|ready|failed`）
5. 前端轮询或 WS/SSE 订阅状态；`ready` 后可进列表、可被 chat matches 命中

**前端要点**
- 进度：loaded/total；不可知时用不确定进度条
- 失败：保留 file 引用一键重试；区分网络失败 vs 类型拒绝
- 不要把大文件 base64 塞进 chat message；只传 `fileId`
- 列表乐观插入「处理中」卡片，失败可删可重试

**小程序**：单文件大小与并发受限；需分片时看平台 API；域名与 https 同样要配。

**业务例子**：Prisma `Doc` + `DocEvent` 记录生命周期；Admin 看状态机，C 端只关心 ready 后能问、能打开。
