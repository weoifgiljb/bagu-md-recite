# 题：Agent 多步时的进度时间线 UI？

## 面试官可能怎么问

- 如何让用户看懂 Agent 在干什么？
- 失败步骤怎么展示与重试？
- 时间线和聊天气泡如何摆放？

## 口述结构（90 秒）

1. 垂直步骤：检索→阅读→工具→汇总，当前步动画
2. 失败红态 + 原因摘要 + 重试；默认折叠大日志
3. 时间线挂在该条 assistant 消息上方，最终答案沉底
4. 长时间无更新要有心跳/超时文案

## 参考答案

### 对应问 1：让用户看懂

信息架构：
1. **步骤标题**用人话（「正在检索文档库」），不要只丢 tool 原名
2. **状态色**：running 动画 / done 打勾 / error 红 / waiting 黄
3. **摘要**：输入输出各一行；详情折叠
4. **预估**：若有 `estimated_steps` 可显示进度，没有就不定百分比装准

步骤（实现）：
1. 会话 store 里该 message 挂 `steps: Step[]`
2. SSE/WS 事件 `step_start` / `step_end` 增量更新
3. 渲染垂直时间线组件，与 markdown 气泡解耦

### 对应问 2：失败步骤

1. 该步 `error` + 可读原因（限流、超时、无权限）
2. 提供 **重试本步** / **从头重跑**（产品二选一，说清副作用）
3. 高风险失败后默认**不自动往下走**
4. 大段 stack/日志默认折叠，防吓到用户

### 对应问 3：与聊天区关系

- 时间线 **内嵌在该条 assistant 消息上方**（或左侧窄栏）
- **最终答案固定在底部**，用户滚动仍能找到结论
- 双 Agent：两条泳道或先后步骤；质检完成再点亮「错误数」摘要

**业务例子**：翻译 + 质检 —— 先「批量翻译」步骤，再「质检扫描」；质检 done 后展示错误列表入口。


## 可能追问

- 用户能跳过某步吗？→ 只读步可跳；高风险确认步不能跳。
- 长时间无更新？→ 心跳文案「仍在处理…」+ 超时可取消。
- 移动端空间不够？→ 步骤缩成横向 chips，点开看详情。
