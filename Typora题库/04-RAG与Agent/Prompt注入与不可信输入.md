# 题 15：Prompt 注入与不可信输入：前端要做什么？

## 面试官可能怎么问

- 用户能不能通过输入覆盖系统提示？产品上怎么表达？
- 前端展示层如何隔离不可信内容？
- 文档内容进 RAG 时前端还要注意什么？

## 先自己答（90 秒）

## 参考答

**认知**：Prompt 注入主要靠**后端/模型侧**防护（系统提示隔离、工具权限、输出策略）；前端不能「防住全部」，但要避免二次伤害。

**前端职责**
1. **展示隔离**：用户消息、助手消息、系统提示在 UI 上分区；不要把系统提示完整暴露给可复制区域（视产品安全策略）
2. **不可信渲染**：用户/模型/文档 HTML 一律按 XSS 题消毒
3. **产品文案**：说明「助手只会基于授权文档与策略回答」；对明显注入尝试可提示「已忽略非常规指令」（若后端返回该标记）
4. **工具确认**：涉及删除、外发、改权限的 tool call，前端做人工确认（见 Agent 题）

**不要宣称**：前端加个关键词过滤就「解决了注入」。

**业务例子**：翻译/质检 Agent 的系统角色固定在服务端；用户改的是待译文案与术语表，而不是覆盖 agent 身份。

## 可能追问

- 把用户消息标成 system 能防吗？→ 不能，角色由服务端组装。
- 文档投毒？→ 入库审核 + 引用展示让人可追溯。
