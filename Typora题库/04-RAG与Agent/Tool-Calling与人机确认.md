# 题：Tool Calling / 高风险工具的前端展示与人工确认？

## 面试官可能怎么问

- 多步 Agent 的 tool call 在 UI 上怎么呈现？
- 哪些工具必须 Human-in-the-loop？确认卡含什么？
- 流式 tool call 参数未完整时前端怎么做？

## 口述结构（90 秒）

1. 步骤条与最终答案分离：中间 JSON 不是答案
2. 高风险写操作必须确认卡：影响范围 + 允许/拒绝
3. 参数未完整：显示「组织参数中」，禁止提前执行
4. 拒绝后：Agent 改道或中止，状态写回时间线

## 参考答案

### 对应问 1：tool call 怎么呈现

**展示模型**
- 时间线/步骤条：`planning → tool:search → tool:translate → critique → final`
- 每步字段：标题、状态（`running|done|error|waiting_confirm`）、可折叠 I/O 摘要（**脱敏**：密钥、PII）
- **最终回复**与中间步骤分区：用户不会把中间 JSON 当成答案

步骤（前端状态机）：
1. 收到 `tool_call` 事件 → 追加步骤 `running`
2. 工具返回 → 更新摘要、状态 `done`/`error`
3. 全部完成 → 渲染 `final` 气泡

### 对应问 2：何时人工确认、确认卡含什么

**必须确认（示例）**：写库、覆盖译文、发消息、扣费、删文档、改权限。

确认卡内容：
1. 工具名与一句话意图
2. **影响范围**（哪些 key/文档/用户）
3. 关键参数摘要（脱敏）
4. 按钮：允许 / 拒绝；可选「允许并记住同类」（谨慎）

步骤：
1. 后端标记 `requires_confirmation`
2. UI 卡住时间线在 `waiting_confirm`
3. 用户允许 → 带 `confirmation_id` 继续；拒绝 → `cancelled`，Agent 改道或中止

**业务例子**：翻译 Agent 批量回填前弹出「将写入 N 个 locale 格」；质检 Agent 只读可不确认。

### 对应问 3：流式参数未完整

1. 流式拼接 `arguments` 字符串
2. JSON 未闭合前：UI 显示「组织参数中…」，**不调用本地副作用**
3. 解析成功且通过 schema → 才进入执行或确认
4. 解析失败 → 步骤 `error`，提示重试/改道


## 可能追问

- 步骤太多怎么刷？→ 默认折叠，仅展开当前/失败/待确认。
- 确认超时？→ 步骤失败或回退；避免无限占用锁。
- 双 Agent（翻译+质检）？→ 两泳道或先后步骤；写库确认放在翻译回填前。
