# 题：文档库检索式助手：search → 展示 → 打开文档？

## 面试官可能怎么问

- 检索式助手的前端主路径是什么？
- pending 与 searchMatches 状态怎么设计？
- 和「答案引用 UI」如何拼在同一条消息里？

## 口述结构（90 秒）

1. 提问→pending→matches+reply→点击打开 Doc
2. phase + 消息级 matches，防串台
3. 先骨架 matches 再填 reply，用户能立刻点依据
4. 空结果与可追溯策略和引用题对齐

## 参考答案

### 对应问 1：主路径

1. 用户提问 → `pending`（检索/生成中）
2. 后端 search → 返回 `matches` + `reply`
3. UI 展示 matches → 点击打开 Doc
4. 可选：Doc 内继续追问（带 `docId` 范围）

### 对应问 2：状态

- `phase: 'idle'|'searching'|'answering'|'done'|'error'`
- `searchMatches` 挂在**该条** assistant 消息上，与 `messages` 数组同行
- 请求世代号：过期响应不写回

### 对应问 3：和引用 UI 拼装

同一条消息建议布局：
1. 上方/侧：matches 卡片（可点）
2. 下方：reply；若有脚注编号与 matches 序号对齐
3. 无 matches：弱提示/拒答，不渲染假引用

**业务例子**：非真 LLM 演示检索也按此路径；换模型时 UI 契约不变。


## 可能追问

- 无结果？→ 空态引导上传/换关键词。
- 搜索与聊天是否同一 API？→ 可合并为 chat 返回 matches。
- 先到 matches 后到 reply？→ 可以；先可点依据再打字机出字。
