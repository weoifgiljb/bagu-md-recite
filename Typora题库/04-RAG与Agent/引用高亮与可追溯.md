# 题：引用高亮与「答案必须可追溯」前端怎么做？

## 面试官可能怎么问

- 什么叫可追溯？前端如何保证？
- 没有字符级 offset 时怎么做高亮？
- 无匹配时要不要硬答？文案怎么写？

## 口述结构（90 秒）

1. 可追溯：能从答案跳到具体文档/片段核实
2. 强制引用列表；无引用则拒答或警告
3. 无 offset：文档级追溯 + snippet，不假装精确高亮
4. 审阅场景偏拒答，避免胡编政策条款

## 参考答案

### 对应问 1：可追溯定义与前端保障

**可追溯**：用户能从答案跳到**具体文档（最好是片段）**核实，而不是一段无法验证的话。

前端保障步骤：
1. 协议要求 assistant 带 `citations` / `matches`（id、title、snippet、可选 start/end）
2. UI **强制展示引用列表**；脚注编号与列表对齐
3. 点击 → 打开 Doc；有锚点则滚动；复制答案可附带来源标题
4. 引用被删 → 「来源已下架」，不要 404 白屏

### 对应问 2：没有字符级 offset

降级策略（诚实）：
1. **文档级**追溯：只能打开整篇 + 展示后端给的 `snippet`
2. 关键词在客户端 **模糊定位**（可选，需声明不保证）
3. **禁止**伪造 `start/end` 假装精确高亮

有 offset 时：
1. 打开文档 → 滚动到 start
2. 高亮 `[start, end)`；注意 Markdown/富文本映射不要错位

### 对应问 3：无匹配硬不硬答

审阅/合规助手推荐：
1. **拒答/弱答**：「未在文档库找到依据，请换问法或先上传文档」
2. 通识回答必须加警告条：「非基于当前文档库」

信息架构：主区 `reply`；侧栏/底部 `matches`（标题、摘要、分数）；TopK +「查看更多」。


## 可能追问

- 多文档综合？→ 多脚注，避免揉成无法点击的一团。
- matches 很多？→ TopK，剩余折叠。
- 点击后回对话？→ 半屏文档或保留 conversation 栈。
