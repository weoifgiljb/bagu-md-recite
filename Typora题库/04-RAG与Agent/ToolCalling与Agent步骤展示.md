# 题 16：Tool Calling / Agent 步骤的前端展示与人工确认？

## 面试官可能怎么问

- 多步 Agent 在 UI 上怎么呈现？
- 何时需要人工确认？
- 翻译 agent 与质检 agent 双角色怎么讲？

## 先自己答（90 秒）

## 参考答

**展示模型**
- 时间线/步骤条：`planning → tool:search → tool:translate → critique → final`
- 每步：标题、状态（running/done/error）、可折叠输入输出摘要（注意脱敏）
- 最终回复与中间步骤分离，避免用户以为「中间 JSON 就是答案」

**人工确认（Human-in-the-loop）**
- 高风险工具：写库、发消息、扣费、覆盖译文
- UI：确认卡（影响范围 + 允许/拒绝）；拒绝后 Agent 改道或中止

**双角色例子（简历）**
- **翻译 Agent（主）**：批量 i18n key → 产出译文
- **质检 Agent（参与）**：对照规则/术语检查 → 报错列表
- 前端可左右栏：译文预览 | 质检问题列表；一键跳到出问题的 key

**业务例子**：SaleSmartly 等场景下，步骤可见能降低「黑盒恐惧」，也方便演示 132→52 的质检闭环（指标另题）。

## 可能追问

- 步骤太多怎么刷？→ 默认折叠，仅展开失败/当前步。
- 流式 tool call 参数？→ 参数未完整前不执行，UI 显示「组织参数中」。
