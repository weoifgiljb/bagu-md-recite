# 题 20：为什么 `height: 100%` 经常不生效？

## 面试官可能怎么问

- 子元素 100% 高度塌了？
- html/body 要怎么写？
- 和 flex:1 比呢？

## 口述结构（90 秒）

1. 百分比高度要求父元素有**明确高度**，否则 % 算不成
2. 常需 `html, body, #app { height: 100%; }` 整条链
3. 更稳：父 Flex 列布局，子 `flex: 1; min-height: 0`
4. 也可用 `100vh` / 更好的 `100dvh`（注意移动端地址栏）

## 参考答案

### 1. 子元素 100% 高度为啥塌？（对应第 1 问）

- 规范：`height: %` 相对父级 **content 高度**；父高是 `auto`（由内容撑开）时，子的 % 高度通常无效，表现像 `auto`。
- 典型：只给 `.page { height:100% }`，但 `html/body` 没高度 → 整链断了。

**遇见问题 → 怎么办**
1. DevTools 看父级 computed height 是否为具体像素。
2. 补链或改 Flex（见下）。
3. 验收：子元素高度随视口/父容器变化，而不是随内容缩成一条。

### 2. html/body 要怎么写？（对应第 2 问）

```css
html, body, #app {
  height: 100%;
  margin: 0;
}
.page {
  height: 100%;
  display: flex;
  flex-direction: column;
}
```

只写 `body { height:100% }` 而 `html` 仍 auto，不少浏览器仍会断链，**html 和 body 一起写**。

### 3. 和 flex:1 比呢？（对应第 3 问）

聊天页/后台壳子更推荐 Flex，少依赖 % 链：

```css
.page {
  height: 100%;              /* 或 min-height: 100dvh */
  display: flex;
  flex-direction: column;
}
.messages {
  flex: 1;
  min-height: 0;             /* 关键：否则子项无法内部滚动 */
  overflow: auto;
}
.composer { flex: none; }
```

| 写法 | 优点 | 注意 |
| --- | --- | --- |
| `%` 高度链 | 概念简单 | 链一断就失效 |
| `flex:1` | 剩余空间分配清晰 | 要 `min-height:0` |
| `100vh` | 不靠父高度 | 移动端地址栏；优先 `dvh`/`svh` |

**业务例子**：外层 column + `height:100%`，消息区 `flex:1; overflow:auto`，输入框固定底部。

## 可能追问

- `100vh` 被浏览器 UI 挡住？→ 用 `100dvh` / `100svh`，或 `--vh` JS 方案。
- `min-height:100%`？→ 内容少时至少一屏，内容多可继续长。
- Grid 呢？→ `grid-template-rows: 1fr auto` 同样能分剩余空间。
