# 题 37：哪些情况会创建新的层叠上下文？（加深）

## 面试官可能怎么问

- 根元素？
- opacity/transform？
- flex 子项 z-index？

## 口述结构（90 秒）

1. **文档根**（html）本身是一个层叠上下文
2. 常见创建者：定位元素且 `z-index` 非 `auto`；`opacity < 1`；`transform`/`filter`/`perspective`/`will-change` 等；`position: sticky/fixed`（按规范亦参与）；`isolation: isolate`
3. **Flex/Grid 子项**：即使 `position:static`，只要 `z-index` 非 `auto` 也会新建上下文
4. 子元素的 `z-index` 再大，也很难「跳出」父上下文去和外面比——弹层被挡先查祖先

## 参考答案

### 1. 根元素（回答该问）

页面初始就有根层叠上下文。所有元素的层叠最终接到这棵树上。比较 `z-index` 前要先确认双方是否在**同一父上下文**里。

### 2. 常见创建条件清单（含 opacity/transform）

面试够用的一张表：

| 条件 | 说明 |
| --- | --- |
| 根元素 | 始终存在 |
| `position` 为 `relative/absolute` 且 `z-index` ≠ `auto` | 经典 |
| `position: fixed/sticky` | 会创建（与实现细节相关，面试按「会」记） |
| `opacity` 小于 1 | **不必定位**；`opacity:0.99` 也会 |
| `transform` / `filter` / `perspective` / `backdrop-filter` 不为 none | 动画、吸顶坑常见元凶 |
| `will-change` 为上述部分值 | 提前建层 |
| `isolation: isolate` | 显式新建 |
| `mix-blend-mode` 不为 normal | 混合相关 |
| Flex/Grid **子项** `z-index` ≠ `auto` | 见下节 |

```css
/* 这些都会让 .panel 变成新上下文，内部 z-index 出不去 */
.panel { opacity: 0.99; }
.panel { transform: translateZ(0); }
.panel { filter: blur(0); } /* 有的写法也会 */
```

### 3. Flex 子项的 z-index（回答该问）

```css
.row { display: flex; }
.item {
  z-index: 10; /* 子项不必 position:relative 也会形成层叠上下文 */
}
```

Grid 子项同理。这和「只有定位元素才能吃 z-index」的过时说法要区分开。

### 4. 排查弹层被挡（步骤）

1. 看弹层 `z-index` 是否够大——不够就加大（同一上下文内）。
2. 若仍被挡：在 DevTools 看祖先有无 `transform`/`filter`/`opacity<1`/`will-change`。
3. 有则：要么去掉祖先副作用，要么把弹层 **Teleport/挂到 body**（Vue/React Portal），让它和页面顶层比。
4. 提高「整层」上下文，而不是只给内部小孩加很大的 z-index。

```css
/* 错误预期：父有 transform 时，子 z-index:99999 仍可能输给外面的兄弟层 */
.modal-parent { transform: translateX(0); }
.modal { position: absolute; z-index: 99999; }
```

## 可能追问

- `isolation: isolate`？→ 显式建上下文，常用于混合模式隔离或约束层叠。
- `mix-blend-mode`？→ 会创建/参与特殊层叠，和隔离一起考。
- 和 stacking level 顺序？→ 同一上下文内：背景边框 → 负 z-index → 块级 → float → 行内 → z-index:auto/0 → 正 z-index（口述大意即可）。
