# 题 7：重排（回流）和重绘是什么？怎么少踩？

## 面试官可能怎么问

- 什么操作触发回流？什么只重绘？
- 为什么说回流贵？和合成层、GPU 的关系？
- 读布局属性为什么会强制同步布局？
- 列表动画、表格高频更新你怎么优化？

## 口述结构（90 秒）

1. 回流：几何/结构变了，要重新算布局；重绘：外观变了但几何大体不变
2. 回流通常连带重绘；两者都可能影响帧率，回流更贵
3. 能用 `transform`/`opacity` 做动画尽量走合成，少改 `top/width`
4. 避免布局抖动：批量读再批量写；用 `requestAnimationFrame`；虚拟列表减 DOM
5. 工具：Performance 面板看 Long Task / Layout

## 参考答案

### 1. 定义（口述版）

- **重排（Reflow / Layout）**：元素尺寸、位置、结构变化，浏览器重新计算布局树。  
- **重绘（Repaint）**：颜色、阴影、可见性等外观变化，几何不变时主要重绘。  
- 现代引擎还有 **合成（Composite）**：`transform`/`opacity` 等常在合成层上变，代价更低（仍要会说「不是绝对零成本」）。

### 2. 常见触发（记类别）

| 更易回流 | 更偏重绘/合成 |
| --- | --- |
| 改 `width/height/top/left/margin` | 改 `color/background-color` |
| 改文字、字体、显示隐藏（`display`） | `visibility`/`opacity`（opacity 常走合成） |
| 插入/删除 DOM、改类名导致布局变 | `transform` 位移动画 |
| 读 `offsetHeight` 等后立刻写样式 | `box-shadow` 等（仍可能贵，看范围） |

### 3. 强制同步布局（经典坑）

```js
// 坏：读-写-读-写交错，每次读可能强制上一次写立刻布局
el.style.width = '100px';
void el.offsetWidth;          // 强制布局
el.style.height = '100px';
void el.offsetHeight;
```

```js
// 好：先批量读，再批量写
const w = el.offsetWidth;
const h = el.offsetHeight;
el.style.width = w + 10 + 'px';
el.style.height = h + 10 + 'px';
```

或把写放到 `requestAnimationFrame` 里，与帧对齐。

### 4. 遇到问题怎么办（卡顿排查步骤）

1. **复现**：操作列表滚动、输入、动画时是否掉帧。  
2. **Performance 录制**：看 Main 里是否频繁 **Layout/Recalculate Style**；有无紫色长条。  
3. **定位代码**：是不是循环里读 `offset*`/`getBoundingClientRect`；是不是每次 keypress 都改上千节点 class。  
4. **改法优先级**：  
   - 动画改 `transform/opacity`，少改 `top/width`  
   - 类名切换代替一条条改 style  
   - 离线 DOM：`DocumentFragment` 批量插入  
   - 大列表虚拟化；表格别每格独立重排敏感样式  
   - `content-visibility` / 含尺寸的骨架减少离屏工作（懂概念即可）  
5. **验收**：同样操作下 Layout 次数下降、交互跟手。

```css
/* 位移动画：优先 */
.drawer {
  transform: translateX(0);
  transition: transform .2s ease;
}
.drawer.is-off {
  transform: translateX(100%);
}
```

```css
/* 慎用：每帧改 left 易回流 */
.drawer { left: 0; transition: left .2s; }
```

**业务例子**：拖拽改宽度时，用 `transform` 预览，mouseup 再落真实 `width`；聊天列表流式输出时节流 DOM 更新，避免每 token 全表回流。

## 可能追问

- `display:none` vs `visibility:hidden`？→ `none` 不影响布局占位（会回流去掉）；`hidden` 占位仍在，多偏重绘。  
- `will-change`？→ 提示浏览器预提升层，滥用浪费内存。  
- 重绘一定比回流便宜吗？→ 大面积重绘也不便宜；以 Performance 为准。
