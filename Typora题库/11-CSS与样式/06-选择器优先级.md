# 题 6：CSS 选择器优先级怎么算？如何避免样式打架？

## 面试官可能怎么问

- 优先级公式 / 权重怎么比？
- `!important`、内联、属性选择器、`:is/:where/:has`？
- 为什么改了类名不生效？你怎么查？
- 工程上怎么降低优先级战争？

## 口述结构（90 秒）

1. 比较顺序：是否 `!important` → 来源（用户/作者等，面试常简说）→ 层叠层 → **选择器特异性** → 先后顺序
2. 特异性口诀：内联 > id > class/属性/伪类 > 元素/伪元素；`!important` 另算
3. `:where()` 特异性为 0；`:is()` 取参数里最高；`:not()` 看参数
4. 排查：DevTools Computed → 看被谁划掉；工程上靠 BEM/CSS Modules/低特异性 + 设计 token

## 参考答案

### 1. 特异性（常用记法）

用四元组 `(内联, id, class/属性/伪类, 元素/伪元素)` 比较，从左到右：

| 选择器 | 大致权重 |
| --- | --- |
| 内联 `style=""` | 1,0,0,0 |
| `#nav` | 0,1,0,0 |
| `.btn`、`[type]`、`:hover` | 0,0,1,0 |
| `div`、`::before` | 0,0,0,1 |
| `*`、`:where(...)` | 0 |
| `!important` | 翻盘器，能盖同来源非 important；别滥用 |

```css
/* 0,1,0,0 胜过 0,0,5,0 */
#app .a .b .c .d { color: red; } /* 仍可能输给 #title */
#title { color: blue; }
```

注意：**不进位死记**（不是 10 个 class 等于 1 个 id），按列比较即可。

### 2. 层叠相关（面试加分）

- 同样特异性：后写的覆盖先写的（同一层内）。  
- 现代：`@layer` 可规定层之间的顺序，层内再用特异性。  
- 继承来的样式特异性最低一档，直接选中元素的声明优先。

```css
@layer reset, base, components, utilities;
```

### 3. 遇到问题怎么办（样式不生效排查）

1. **DevTools → Elements → Styles**：看规则是否被划掉；上方是谁赢了。  
2. **看 Computed**：最终 `color/display` 到底是多少。  
3. **常见原因清单**：  
   - 特异性不够（被 `#id` 或更长选择器压住）  
   - 被 `!important` 压住  
   - 选错元素（类名写在子上，你改父）  
   - 打包顺序/异步 CSS 后加载覆盖  
   - 作用域：CSS Modules 哈希、Shadow DOM、iframe  
   - 浏览器前缀/无效属性被丢弃  
4. **临时验证**：在 DevTools 里改一条更高特异性或勾掉对方规则，确认是优先级问题不是 DOM 结构问题。  
5. **正确修复**（按推荐顺序）：  
   - 提高语义化类名落点，而不是叠 `#a #b #c`  
   - 用更近的单一类覆盖组件 API（如 `.Button--primary`）  
   - 万不得已再 `!important`（工具类/第三方覆盖）  
```css
/* 差：一路加权重 */
#page .content ul li a span { color: red; }

/* 好：组件根上一个类 */
.Link--danger { color: var(--danger); }
```

### 4. 工程策略（口述收尾）

- **低特异性默认**：多类名组合，少 ID 选样式。  
- **隔离**：CSS Modules / scoped / Shadow DOM，减少全局碰撞。  
- **约定**：工具类层最后；业务组件不写裸标签选择器扫全局。  
- **主题**：颜色走 CSS 变量，少写死选择器覆盖。

**业务例子**：改 Button 颜色不生效——先看 UI 库是否用了更高特异性或 `!important`；用官方 `type/class` API 或 `:deep`/包装类覆盖，而不是再叠三层后代选择器。

## 可能追问

- `:is(.a, #b)` 特异性？→ 按参数中最高的那个算。  
- `:where` 用途？→ 写复杂选择器但不抬权重，方便外面覆盖。
- `:has`？→ 父选子条件（如 `.card:has(.badge)`）；特异性含 `:has` 参数，注意性能别滥用宽泛通配。  
- 内联和 `!important` 谁强？→ 同来源下，带 `!important` 的作者样式可盖内联非 important；两边都 important 再比特异性/顺序。面试说清「别靠 important 对刚」即可。
