# 题 1：盒模型是什么？box-sizing 有什么用？

## 面试官可能怎么问

- 标准盒和 IE 盒区别？
- 为什么很多项目 reset 成 border-box？
- width 算不算 padding、border、margin？

## 口述结构（90 秒）

1. 盒子由 content、padding、border、margin 组成
2. 标准盒（content-box）：`width`/`height` 只指内容区
3. border-box：`width`/`height` 含 content + padding + border，**不含 margin**
4. 老 IE 怪异模式类似 border-box；现代用 `box-sizing` 显式控制，项目常全局 border-box 好算布局

## 参考答案

**标准盒 vs IE（怪异）盒**
- W3C 标准模式默认 `content-box`：你写的 `width` 是内容宽，padding/border 往外加，元素占位更宽。
- 老 IE 怪异模式：`width` 更像「边框盒」宽（含 padding、border），和现在的 `border-box` 思路接近。
- 今天面试说「IE 盒」一般是在对比这两种宽度算法；现代浏览器用 `box-sizing` 切换，不要靠怪异模式。

**算一下（常踩坑）**
```css
.box { width: 100px; padding: 10px; border: 2px solid; }
```
- `content-box`：**内容**宽 100；水平方向一共占 `100 + 10+10 + 2+2 = 124`（左右 padding 各 10，左右 border 各 2）。
- `border-box`：100 已经是「到 border 外缘」的宽，内容区被挤小；**margin 仍然在外面**，不进 `width`。

注意：只写 `padding: 10px`、没有 border 时，content-box 下宽度占位是 `100+20=120`；有人说成 110，是只加了一侧，是错的。

**为什么全局 border-box**
两栏、网格里设 `width: 50%` 再加 padding，用 content-box 容易撑破；border-box 更符合「这个盒子总体就这么宽」的直觉。

```css
*, *::before, *::after { box-sizing: border-box; }
```

## 可能追问

- margin 算进 box-sizing 吗？→ 不算，两种盒模型里 margin 都在盒子外。
- margin 合并？→ 相邻兄弟垂直 margin 常取较大值；与 box-sizing 是另一件事，可用 BFC/`gap`/padding 规避。
- 替换元素（img）？→ 也有盒模型，还有固有尺寸；常见 `max-width:100%` + `object-fit`。
