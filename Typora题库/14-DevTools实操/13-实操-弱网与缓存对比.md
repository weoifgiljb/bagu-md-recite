# 题 13：实操——Disable cache + 弱网限速，对比首屏和接口

## 面试官可能怎么问

- 怎么模拟差网络？
- Disable cache 和硬刷新有什么关系？
- 你怎么区分「资源太大」还是「接口 TTFB 慢」？

## 口述结构（90 秒）

1. Network 开 Disable cache，限速 Fast 3G
2. 刷新录瀑布，看是谁堵
3. Timing 分清 TTFB vs Download
4. 关掉限速再对比，避免误判

## 参考答案

### 操作步骤（照着点）

1. F12 → **Network**。
2. 勾选 **Disable cache**（仅 DevTools 打开时生效）。
3. 在面板顶部 **No throttling** 下拉，选 **Fast 3G**（或 Slow 3G）。
4. Clear → **Ctrl+Shift+R** 硬刷新（或点 Performance/Network 的刷新录制，二选一即可）。
5. 等加载结束，按 **Time** 排序，点开最慢的 1～3 条：
   - 静态 JS/CSS：**Download** 长 → 体积/分包问题
   - 接口：**Waiting (TTFB)** 长 → 后端或链路
6. 看瀑布是否大量 **Queueing**（同域并发、HTTP/1）——HTTP/2 站点通常好一些。
7. 测完把 throttling 改回 **No throttling**，并记住关 DevTools 后 Disable cache 就失效。

### 对比实验（建议做一次）

1. 第一次：Disable cache + Fast 3G，截图最慢请求 Timing。
2. 第二次：不勾 Disable cache，同限速再刷，看哪些变 `(memory cache)` / `(disk cache)`。
3. 口述结论：缓存命中后首屏改善多少，说明你理解缓存策略而不只是背名词。

## 可能追问

- 为什么线上用户仍慢、你本地很快？→ CPU/网络/地区；用限速和 4× CPU 逼近。
- 304 还要不要优化？→ 协商缓存仍有请求往返；长期不变的用长 hash + 强缓存更好。
