# 题 10：实操——录一段滚动/输入卡顿，圈出 Long Task

## 面试官可能怎么问

- 你怎么用 Performance 证明「卡」不是错觉？
- Long Task 阈值大概多少？找到之后怎么下钻？
- 录太长看不过来怎么办？

## 口述结构（90 秒）

1. Performance 开 Screenshots，可选 CPU 4×
2. Record → 立刻滚动/打字 3～8 秒 → Stop
3. 看 FPS 红条，框选卡顿区间
4. 找 Long Task / 最宽黄条 → Bottom-Up 看 Self

## 参考答案

### 操作步骤（照着点）

1. F12 → **Performance**。
2. 右上设置（齿轮）：勾选 **Screenshots**；需要放大问题时把 **CPU** 调成 **4× slowdown**。
3. 确认页面已在「会卡」的状态（长列表、对话很多气泡等）。
4. 点圆点 **Record**（或 Ctrl+E）。
5. **马上**做复现：快速滚动列表，或在输入框连续打字，控制在约 **5 秒**。
6. 再点 **Stop**，等解析完成。
7. 看顶栏 **FPS**：有红色/缺口 = 掉帧。
8. 在时间轴上 **拖拽框选** 掉帧最明显的一小段（不要看整段）。
9. 在 **Main** 轨道找：
   - 灰色长条 / 红三角提示的 **Long Task**（主线程连续工作超过约 50ms）
   - 特别宽的 **黄色** Scripting 块
10. 点中该块，下方切到 **Bottom-Up**，按 **Self Time** 排序，记下 Top3 函数名/文件名。
11. 有 source map 时点函数名跳源码；没有就根据文件名 + 操作时机猜业务函数（如 `renderList`）。
12. （可选）改完代码后 **用同一操作再录一段**，对比 Summary 里 Scripting 总时间是否下降。

### 验收标准（练完能做到）

- 能指着屏幕说：「这段 Long Task 里 Self 最高的是某某」。
- 知道框选比整段硬看更重要。

## 可能追问

- 为什么要 4× CPU？→ 办公本/桌面机太快，问题被掩盖。
- 只有 Rendering 紫条很高呢？→ 去查频繁 Layout/复杂样式，不是纯 JS 算得慢。
