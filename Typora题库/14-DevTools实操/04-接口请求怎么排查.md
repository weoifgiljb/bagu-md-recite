# 题 4：接口失败、CORS、鉴权问题在 Network 里怎么查？

## 面试官可能怎么问

- 401 和 CORS 失败在面板上怎么区分？
- 预检 OPTIONS 是什么？什么时候出现？
- 流式/SSE 请求在 Network 里长什么样？
- Copy as cURL 有什么用？

## 口述结构（90 秒）

1. 点开请求四件套：Headers / Payload / Preview / Response
2. 先看 Status 和 Response 正文，再看 Request Headers（Token、Content-Type）
3. CORS：常显示 failed，点进看是否被浏览器拦；对照 OPTIONS
4. 复制为 cURL 丢到终端对比「是前端封装问题还是服务端问题」

## 参考答案

### 1. 点开一条请求看什么（固定顺序）

1. **General**：Request URL、Method、Status Code、Remote Address。
2. **Request Headers**：`Authorization` / Cookie、`Content-Type`、`Origin`。
3. **Request Payload / Query String**：有没有传错 id、漏字段（注意 Form Data vs JSON）。
4. **Response / Preview**：业务错误码、message；JSON 用 Preview 更易读。
5. **Initiator**：哪个文件哪一行 `fetch`/`axios` 发的。

### 2. 常见状态怎么认、下一步

| 现象 | 面板表现 | 下一步 |
|------|----------|--------|
| 未登录 | 401，Body 常有 message | 看请求头有没有带 Token；Application 里 Cookie/Token 是否过期 |
| 没权限 | 403 | 对照角色/资源 id；别和 CORS 搞混 |
| 路径错 | 404 | 对一下 baseURL、代理、环境变量 |
| 服务挂/异常 | 500/502/504 | Response 正文/网关页；把耗时和后端日志时间对齐 |
| CORS | Status 常 `(failed)`，Console 有 CORS 红字 | 看有没有 OPTIONS；响应是否缺 `Access-Control-Allow-Origin` |
| 取消 | (canceled) | 竞态 abort、路由切换、StrictMode 双调用 |

注意：**CORS 失败时你在 Response 里经常看不到正文**——浏览器拦截了前端读响应，不等于服务器没返回。

### 3. 预检 OPTIONS

跨域且「非简单请求」（自定义头如 `Authorization`、`Content-Type: application/json`、非 GET/POST 简单表单等）时，浏览器先发 **OPTIONS**。

实操：

1. Network 里同一路径先 OPTIONS 再 POST。
2. OPTIONS 必须 200/204，并带允许的 Method/Headers。
3. 若 OPTIONS 4xx/被网关挡，真正的 POST 不会成功。

### 4. 复制请求做对照

右键请求 → **Copy → Copy as cURL**（或 Copy as fetch）：

- 在终端跑通：说明服务端 OK，问题多半在前端封装、拦截器、环境代理。
- 终端也不通：把问题甩给后端/网关，并附 URL+Status+关键 Header（打码 Token）。

### 5. SSE / 流式（AI 对话常见）

1. Type 可能是 **eventsource** 或 fetch，Status 200 后长时间 **pending**。
2. EventStream / Response 会陆续出 `data:` 行；中途断了看是网络还是服务端结束。
3. 若 Nginx 缓冲导致「一下子涌出来」：和运维查 `proxy_buffering`；这是面试加分点。
4. 取消生成：看是否出现 canceled，以及 AbortController 是否在 Initiator 栈里。

### 6. 和业务结合的三步口述

「先 Network 滤 XHR → 看 Status 和 Response → 401 查 Token，CORS 查 OPTIONS 与 ACAO，慢再看 Timing 的 TTFB。」

## 可能追问

- 为什么有的环境有代理 `/api` 本地正常、预发跨域？→ 本地 devServer 代理同源，预发是真浏览器跨域。
- Cookie 跨站带不上？→ SameSite、Secure、域名、是否前端 `credentials: 'include'` + 后端 `Allow-Credentials`。
