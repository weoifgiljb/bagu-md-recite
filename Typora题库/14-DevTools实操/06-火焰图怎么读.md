# 题 6：Performance 火焰图怎么读？Self time 和 Total time 有什么区别？

## 面试官可能怎么问

- 火焰图横轴纵轴分别是什么？
- 怎么快速找到「罪魁祸首」函数？
- Bottom-Up 和 Call Tree 怎么用？
- Long Task 是什么？

## 口述结构（90 秒）

1. 横轴时间，纵轴调用栈；块越宽占时越久
2. 先找最宽的黄条 / 长任务红标，再往下钻
3. Total = 自己+孩子；Self = 自己；优化看 Self 高的叶子
4. Bottom-Up 找「谁吃自我时间」，Call Tree 看调用路径

## 参考答案

### 1. 火焰图怎么看

- **横轴**：时间（可缩放、框选）。
- **纵轴**：调用栈；上面是调用者，下面是被调用者（Chrome Main 火焰图常见是「栈底在下」的形态，以你面板为准：总之 **父子是层层调用**）。
- **宽度**：该函数（及其子调用在 Total 视角下）占用的时间长度。
- **颜色**：大致黄=脚本，紫=样式/布局，绿=绘制（以图例为准）。

块上有函数名 / 文件名时，点它会在下方详情里看到 URL 与耗时。

### 2. Self time vs Total time

- **Total time**：该函数从进入到退出的总时间（包含它调用的子函数）。
- **Self time**：刨掉子调用，**自己身子**里的时间。

优化口诀：

1. 先看 Total 很宽的块 → 知道哪条调用链贵。
2. 再在 Bottom-Up 里按 **Self** 排序 → 找到真正「自己就很慢」的叶子（如巨正则、大 JSON.parse、同步加密）。
3. 若父宽子也宽：可能是「调用太多次」而不是单次逻辑重 → 看调用次数、是否在循环里。

### 3. 三个列表视图

1. **Bottom-Up**：谁 Self 高就打谁；适合找热点函数。
2. **Call Tree**：从根往下看调用路径；适合理解「为什么会进到这个函数」。
3. **Event Log**：按时间列事件；适合对一下精确时刻。

实操：框选卡顿区间 → Bottom-Up → 点开 Group by Activity / 按 Self 排序 → 点函数 → 看右边源码（有 source map 时）。

### 4. Long Task（长任务）

主线程上连续超过约 **50ms** 的任务会标成 Long Task（影响交互、输入延迟）。

图上常见提示：火焰图上方红三角 / 灰色长条。点开看里面是谁：框架 commit、一次算太大的列表、同步 XHR（少见但致命）等。

对策方向：拆工作（`requestIdleCallback` / 分片 / worker）、减渲染量、虚拟列表、防抖。

### 5. 实操口诀（面试可直接背）

1. 框选掉帧那一段。
2. 找最宽的 Scripting 块。
3. Bottom-Up 看 Self Top 3。
4. 点进源码确认是业务代码还是第三方。
5. 改完用同样操作再录一段对比 Summary。

## 可能追问

- 为什么火焰图顶层全是 `performUnitOfWork` / `render`？→ 框架运行时；往下钻到业务组件函数或 heavy 库。
- 没有 source map 怎么办？→ 预发开 map，或用 React/Vue 的组件名 + 操作时机对照。
