# 题 3：Vue3 生命周期有哪些？和 Vue2 / Composition API 怎么对应？

## 面试官可能怎么问

- Options 和 Composition 生命周期怎么一一对应？
- setup / onBeforeMount / onMounted 分别适合干什么？
- 组件销毁时要注意什么？（定时器、监听、请求）

## 口述结构（90 秒）

1. 先画时间线：创建 → 挂载 → 更新 → 卸载
2. Options：beforeCreate/created 被 setup 吸收；其余 beforeMount/mounted…
3. Composition：onBeforeMount、onMounted、onBeforeUpdate、onUpdated、onBeforeUnmount、onUnmounted
4. 数据请求常放 onMounted 或 watch(immediate)；DOM 操作必须 mounted 之后
5. 收尾：卸载清定时器、removeEventListener、abort 请求、断开 WS

## 参考答案

### 1. Options ↔ Composition 对应

| Options API | Composition API | 典型用途 |
| --- | --- | --- |
| beforeCreate / created | `setup()` 本身（同步部分） | 初始化状态、注入、定义方法 |
| beforeMount | `onBeforeMount` | 即将挂 DOM，仍拿不到 el |
| mounted | `onMounted` | 读 DOM、加原生监听、拉首屏数据 |
| beforeUpdate | `onBeforeUpdate` | 更新前读旧 DOM（少用） |
| updated | `onUpdated` | 更新后量尺寸（注意防循环改状态） |
| beforeUnmount | `onBeforeUnmount` | 开始清理 |
| unmounted | `onUnmounted` | 确认清理完成 |
| errorCaptured | `onErrorCaptured` | 子树错误边界 |
| activated / deactivated | `onActivated` / `onDeactivated` | 配合 keep-alive |

Vue3 去掉了 `beforeDestroy`/`destroyed` 命名，改为 `beforeUnmount`/`unmounted`。SSR 还有 `onServerPrefetch`。记对应表时强调：**created 里能干的事，在 Composition 里就是 setup 同步代码**，不必再找一个 `onCreated`。

### 2. setup / 挂载钩子怎么放逻辑

```ts
import { ref, onMounted, onBeforeUnmount, watch } from 'vue'

const el = ref<HTMLElement | null>(null)
const list = ref([])
const keyword = ref('')

// setup 同步：声明状态、纯计算、注册副作用（钩子必须在同步阶段注册）
watch(keyword, (q) => { /* 搜索请求 */ })

onMounted(async () => {
  el.value?.focus()                 // 需要真实 DOM
  list.value = await api.fetchList() // 首屏数据
  window.addEventListener('resize', onResize)
})

onBeforeUnmount(() => {
  window.removeEventListener('resize', onResize)
})
```

落地规则：

1. **`setup` 在 beforeCreate 之前执行**，Composition 不用 `this`。
2. **钩子要在同步阶段注册**；若 setup 顶层先 `await` 再 `onMounted`，可能错过注册窗口（`<script setup>` 顶层 await 会变成异步 setup，需清楚影响）。
3. **DOM**：模板 ref 在 `onMounted` 才有值；也可用 `watchEffect` + `flush:'post'`。
4. **请求**：与路由/props 强相关时，优先 `watch(source, fn, { immediate: true })`，比只写在 `onMounted` 更能覆盖后续变化。
5. **`onUpdated` 里改同一视图依赖** 易死循环；量完尺寸把结果写到「不触发本树重渲染」的地方，或加守卫。

### 3. 销毁时必须清理什么（步骤）

1. **`setInterval` / `setTimeout`** → `clearInterval` / `clearTimeout`。
2. **`window`/`document` 监听** → 同一函数引用 `removeEventListener`。
3. **进行中的请求** → `AbortController.abort()`，防止卸载后写 ref。
4. **WebSocket / EventSource** → `close()` 并摘掉回调。
5. **图表/编辑器/地图** → 调官方 `dispose`/`destroy`。
6. **`$subscribe` / 自建 emitter** → 取消订阅。

```ts
onMounted(() => {
  const ctrl = new AbortController()
  fetch('/api', { signal: ctrl.signal })
    .then(r => r.json())
    .then(d => { data.value = d })
    .catch(e => { if (e.name !== 'AbortError') console.error(e) })
  onBeforeUnmount(() => ctrl.abort())
})
```

**业务例子**：会话页 `onMounted` 建 WS，`onBeforeUnmount` 关闭；keep-alive 列表用 `onActivated` 刷新、`onDeactivated` 停轮询，而不是把 Pinia 清掉。

**验收**：快速进出页面，Network 无「卸载后回写」；反复进入内存与监听器数量不单调涨。

父子生命周期顺序记一句：**创建时自上而下（父 setup → 子 setup），挂载完成自下而上（子 mounted → 父 mounted）**；卸载相反，先子后父。keep-alive 缓存命中时再次进入不会 mounted，只 activated——把「每次露出都要做」的逻辑从 mounted 拆出去，是面试高频加分点。

## 可能追问

- created 里能不能操作 DOM？→ 不能；用 mounted。
- 父子挂载顺序？→ 父 beforeMount → 子全部挂完 → 父 mounted。
- `onMounted` 在 SSR？→ 仅客户端；首屏数据用服务端或 `onServerPrefetch`。
