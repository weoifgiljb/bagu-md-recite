# 题 9：Vue 的虚拟 DOM 和 diff 怎么用大白话讲？

## 面试官可能怎么问

- 什么是虚拟 DOM？一定更快吗？
- Vue3 diff 有什么优化？
- key 的作用？用 index 行吗？

## 口述结构（90 秒）

1. VNode = 真实 DOM 的 JS 描述
2. 数据变 → 新树 → diff → 最小补丁打到真实 DOM
3. 不是银弹：简单场景直接改 DOM 也可能更省；复杂 UI 赢在可维护与批量
4. key 标识身份；Vue3 有静态提升与 PatchFlags

## 参考答案

**对应问 1：是什么 / 是否更快**
虚拟 DOM 让框架用声明式 UI：你改状态，它算差异。  
对比「整页 innerHTML」通常更划算；对比「你精确手写只改一个 textNode」，虚拟 DOM 有额外创建与 diff 成本。工程价值是：跨组件复用、批更新、服务端渲染同构等。

**对应问 2：Vue3 优化**
- **静态提升**：纯静态节点提到渲染函数外，不参与每次对比
- **PatchFlags**：编译期标记动态的 props/文本/子节点，运行时只比脏的部分
- **Block tree** 等：跳过稳定子树  
口述一句：Vue3 把大量优化做在编译期，运行时少做无用功。

**对应问 3：key**
```vue
<div v-for="m in messages" :key="m.id">...</div>
```
- 正确：稳定业务 id  
- 危险：用 index；中间插入/删除时，输入框等状态会错位  
- 同层 diff：类型不同直接替换；类型相同再比 props/children

**业务例子**
聊天列表必须用消息 id；流式输出尽量原地改最后一条内容，减少整列表抖动。

## 可能追问

- 和 React diff？→ 都倾向同层比较；细节与编译优化不同。
- 手动优化？→ `v-once`、`v-memo`、拆小组件减小更新面。
