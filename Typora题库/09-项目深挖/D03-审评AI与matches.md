# 题 12：文档审评 AI：`reply + matches` 前端怎么用？和真 LLM 的关系？

## 面试官可能怎么问

- Nest `/api/ai/chat` 返回什么？
- 没有 matches 时 UI 怎么办？
- 能说成已经接了大模型吗？

## 口述结构（90 秒）

1. 契约：{ reply, matches[] }
2. reply 进气泡；matches 可跳转文档
3. 可无真 LLM：关键词检索演示也按契约开发
4. 空 matches：弱提示/拒答，不假装很懂

## 参考答案

### 对应问 1：返回什么

契约（示意）：`POST /api/ai/chat` → `{ reply: string, matches: Match[] }`。

前端步骤：
1. pending 展示检索/生成中
2. 收到后：`reply` → assistant 气泡
3. `matches` →「相关文档」列表；点击带 `docId` 进详情
4. `matches ?? []` 兜底，防 undefined

### 对应问 2：没有 matches

产品策略（审阅助手偏严格）：
1. **拒答/弱答**：「未在文档库找到依据…」
2. 或通识回答 + 警告条（标明非基于文档库）

不要无「很自信」的假引用。鉴权：DemoToken 等只在服务端约定 Header；**密钥不进小程序包**。

### 对应问 3：能说已经接了大模型吗

**看事实**。当前后端可能是关键词/统计检索 Docs 的演示实现。

稳妥句：
「前端按 `reply + matches` 契约开发；后端现在可以是检索演示，换真 LLM 时 UI 契约不用翻掉。面试我不把它说成已上生产大模型。」


## 可能追问

- 小程序 SSE？→ 能力受限；可用分块轮询或短连接；实验台按平台约束讲。
- Lab delay？→ 仅开发开关，配置在 Admin/服务端，不进生产默认。
- AdminJS 文档状态？→ 可检索态才进 matches；下架文档展示「来源已下架」。
