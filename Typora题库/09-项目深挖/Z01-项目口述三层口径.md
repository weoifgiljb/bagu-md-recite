# 题 14：任何项目开口：当前实现 / 实验台 / 改进设计 怎么分层？

## 面试官可能怎么问

- 为什么要分层？
- 20/40/10 秒骨架是什么？
- 被追问「这上线了吗」怎么答？

## 口述结构（90 秒）

1. 防翻车：改进设计 ≠ 已上线
2. 20s 贡献 + 40s 设计 + 10s 证据边界
3. 三层固定前缀开口
4. 被追问上线：回落到对应层，不硬撑

## 参考答案

### 对应问 1：为什么要分层

面试官在听两件事：你**真实做过什么**，以及你**设计能力边界**。混层会导致：
- 把实验台/设计稿说成生产 → 诚信风险
- 只讲琐碎 CRUD → 显得没有设计深度

分层让你**既能讲深，又不撒谎**。

### 对应问 2：20 / 40 / 10 骨架

1. **20 秒真实贡献**：我负责 X，交付了 Y（可验证）
2. **40 秒设计理解**：链路 → 状态 → 边界 → 异常
3. **10 秒证据边界**：团队基建不是我独立做的；指标如实；改进加前缀

**三层前缀**

| 层 | 固定前缀 | 用在 |
| --- | --- | --- |
| 当前实现 | 「当时落地的是…」 | 实习 / 线上 |
| 实验台 | 「后来用 Taro 把契约跑通时…」 | 文档审评复盘 |
| 改进设计 | 「如果让我继续优化…」 | 任务表 / outbox / 虚拟列表 |

### 对应问 3：「这上线了吗」

模板：
「**当时落地的是** A。**实验台验证了** B。**如果继续优化**会做 C。C 还没上生产。」

把改进设计说成已上线 = 高风险翻车。没有数据支撑的优化 → 讲设计与取舍，不报假指标。


## 可能追问

- 没有数据怎么讲优化？→ 讲瓶颈假设、验证方法、回滚；不报假百分比。
- 团队公共 Table 贡献？→ 说清复用 vs 业务查询/导出快照是我侧。
