# 题 11：小程序列表：刷新/搜索/触底时如何避免旧响应污染？

## 面试官可能怎么问

- loading / noMore / 失败怎么收口？
- 请求世代号实习有没有？
- 切 Tab 卡顿常见原因？

## 口述结构（90 秒）

1. 状态机：idle/loading/success/empty/error/noMore
2. 改筛选：重置页码与 list → 新 seq → 请求
3. 实习或仅有 loading 守卫要如实说；实验台写全 seq
4. 切 Tab 卡顿常是节点膨胀，不是接口慢

## 参考答案

### 对应问 1：状态怎么收口

统一状态：`idle | loading | success | empty | error | noMore`。  
刷新与触底**共享同一套收口**，避免两套 flag 打架。

步骤：
1. 进入 loading（若已是 loading 且同 seq，忽略重复触发）
2. 成功：拼页 / 替换；空 → empty；无下一页 → noMore
3. 失败 → error，保留旧 list 或按产品清空（说清取舍）
4. 触底：仅 `success && !noMore` 时 `page+1`

### 对应问 2：请求世代号

**推荐（实验台已写全）**
1. 每次有效请求 `seq++`
2. 响应返回时比对；过期**整包丢弃**
3. 改筛选 / 搜索：重置 `page=1`、`list=[]`、新 seq

**实习仓库**若仅有 `loading/noMore` 守卫：如实说「当时用 loading 防重入；实验台补了 seq」。

### 对应问 3：切 Tab 卡顿

常见不是接口慢，而是：
- 列表节点膨胀、`setData` 体积大
- 多 Tab 同时挂着重 DOM

优化口述：分页收口、虚拟列表（实验台/改进）、控制 `setData` 字段、图片懒加载；**标明哪层已做**。


## 可能追问

- setData 体积？→ 只 set 变更字段；长列表分页；避免整树拷贝。
- wxParse 图片长文？→ 懒加载、拆段；实验台可换 rich-text 策略。
- 失败重试插到中间？→ 重试用原 page+seq；成功按页覆盖/追加规则写清。
