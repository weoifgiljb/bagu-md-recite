# 题 1：SaleSmartly 翻译 Agent：项目怎么介绍？你负责哪一块？

## 面试官可能怎么问

- 用 90 秒介绍这个项目
- 翻译 agent 和质检 agent 怎么分？你负责哪边？
- 不要把团队基建说成自己独立做的，你怎么划界？

## 口述结构（90 秒）

1. 定位：自研 i18n 工作流，解决 key 量大、机翻不稳、外包慢
2. 两侧：翻译 agent（我主责）vs 质检 agent（同事主责）
3. 链路骨架：CMS 取 key → 术语/上下文 → 模型或直填 → 结构校验 → 回填
4. 分层口径：当前实现是进程内状态；任务表/lease 是改进设计

## 参考答案

> 分层口径：当前实现 / 实验台 / 改进设计 —— 开口先声明，勿串层。

### 对应问 1：90 秒项目介绍

**定位**：SaleSmartly 自研 i18n 翻译工作流，目标是把大量 `i18n_key` 从 CMS/表格译成多语种，并保证占位符、术语、结构不炸。

**口述骨架（按秒）**
1. **痛点（10s）**：key 量大、纯机翻质量不稳、外包周期长。
2. **我负责（20s）**：翻译 agent —— CMS 取待译 key → 拼术语与上下文 → Dify/模型或 `matchExactTerm` 直填 → 结构校验 → 失败重翻 → CMS 回填。
3. **不负责夸大（15s）**：质检 agent、Playwright 门禁是同事主责；我参与联调与对照评测。
4. **落地边界（20s）**：「当时落地的是」进程内状态 + CMS 版本号防重入；「如果补多 worker」才谈任务表 / lease / outbox。
5. **证据（10s）**：对照评测错误数 132→52（另题讲口径）。

### 对应问 2：翻译 vs 质检怎么分

| 角色 | 职责 | 我怎么说 |
| --- | --- | --- |
| 翻译 agent | 产出结构化译文、结构壳校验、回填 | **主责** |
| 质检 agent | 语义复检、评分、发布前质量门禁 | **同事主责**；我参与联调 |

步骤（联调时）：
1. 翻译侧产出 JSON 译文
2. 质检侧按规则/术语表打分或出错误列表
3. 前端或运营侧对照 key 跳转；不把质检流水线说成我独立交付

### 对应问 3：个人边界怎么划

**禁止说错**：质检 agent、Playwright、任务表已上线、整套基建 = 我一个人。

**稳妥说法**：
「翻译链路与结构/术语保护是我主责；质检与门禁是同事主责，我参与接口联调。多 worker 的任务表是改进设计，当时单进程就能跑通业务。」

**业务例子**：新人引导页一批 key 走翻译 agent；质检侧出对照表；指标按错误条数降幅讲，不说「准确率提升 60%」。


## 可能追问

- 质检你参与到什么程度？→ 联调、对照评测、接口契约；不把 Playwright 流水线说成独立交付。
- Dify 和直连模型怎么选？→ 工作流编排/可观测用 Dify；极简或精确术语可直填/直连。
- CMS 表结构？→ 按 record_id + i18n_key + locale 对格；勿编造未确认字段名。
