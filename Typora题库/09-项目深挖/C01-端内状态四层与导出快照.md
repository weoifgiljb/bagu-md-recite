# 题 9：Vue 端内：状态四层和导出快照怎么保证一致性？

## 面试官可能怎么问

- 端内和运营后台有什么区别？
- 筛选/时区/列表/导出如何同源？
- 旧响应怎么丢弃？

## 口述结构（90 秒）

1. 端内 = 客户用的软件本体，服务端真相优先
2. 四层：route query / Pinia / 页面局部 / 请求快照
3. 导出瞬间 freeze 查询快照，job 不读当前页 rows
4. fetchSeq / stateVersion：旧 HTTP/WS 整包丢弃

## 参考答案

### 对应问 1：端内 vs 运营后台

- **端内**：客户用的产品本体（坐席/工作台等），权限与数据以**服务端真相**为准
- **运营后台**：配置、审计、租户运营 —— 不是同一套信息架构

开口先划界，避免把 Admin 能力说成端内功能。

### 对应问 2：筛选 / 时区 / 列表 / 导出同源

**状态四层**
1. `route query`：可分享、可刷新恢复的筛选
2. Pinia：跨页会话级
3. 页面局部：瞬时 UI
4. **请求快照**：一次列表/导出绑定的不可变查询对象

**数据页原则**：筛选 · 时区 · 列表 · 导出 = **同一份查询快照**。

步骤（导出）：
1. 用户点导出
2. **freeze** 当前查询快照（含时区、筛选、排序）
3. 创建导出 job，**只带快照**，不读表格当前 `rows`
4. 用户继续改筛选不影响已提交 job

**时区**：全程毫秒 timestamp；用账号时区算日起点/终点；半开区间；禁止混用浏览器本地时区。

### 对应问 3：旧响应怎么丢弃

1. 每次有效请求 `fetchSeq++`（无效调用不改序号）
2. 写回前校验 `seq === 当前`
3. `stateVersion` 单调递增；旧 HTTP / WS 整包丢弃
4. Socket 权限变更同样走 version，避免「无权限的旧包」盖住新状态


## 可能追问

- Socket 权限变更怎么合？→ 服务端推 version/权限事件，前端抬 version 丢旧包。
- 公共 Table 和个人业务边界？→ 表格基建团队；业务查询快照与导出是我侧。
- 跨日时长口径谁定？→ 产品/后端定义半开区间；前端只消费，不本地乱算。
