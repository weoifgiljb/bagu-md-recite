# 题 3：一个 key 从 CMS 取出到回填，完整链路怎么讲？

## 面试官可能怎么问

- 输入输出是什么结构？
- 术语和上下文怎么进 prompt？
- 校验失败之后走哪？

## 口述结构（90 秒）

1. 取：页面·类别·视图 → 待译 key / 源文 / 目标语种
2. 译：术语命中 + locale profile + 上下文 → 模型或直填
3. 校：结构壳（占位符/标签/重复）
4. 写：成功格立刻回填；失败空置；部分成功不污染

## 参考答案

### 对应问 1：输入输出结构

**输入（示意）**
- `record_id` / `i18n_key` / 源文 / 目标 `locale` / 页面·类别·视图元数据
- 可选：术语表命中、业务上下文、locale profile

**输出**
- 仍是**结构化 JSON**（字段与源结构对齐），不是自由散文
- 回填键：`record_id` + `i18n_key` + `locale` **对格更新**（不是 localStorage）

步骤：
1. CMS/表格按维度取待译行
2. 组装任务 payload
3. 译完得到结构化结果
4. 校验通过 → 写对应 locale 格

### 对应问 2：术语和上下文怎么进 prompt

1. 查术语库：对源文做命中；`matchExactTerm`：**trim 后整串唯一**才允许直填（`聊天`✓ / `开始聊天`✗）
2. 拼 locale profile（语气、标点习惯）+ 业务上下文（页面说明）
3. 送 Dify/模型；精确术语可走直填旁路，跳过模型

### 对应问 3：校验失败之后

1. **结构校验失败** → 当次不写 CMS → 重翻（可换策略）
2. **连续失败** → 失败/长难句队列，人工或后续策略消费
3. **部分成功**：成功 locale 立刻写格；失败保持空；整行仍草稿；全语种齐再待同步

**两条 CMS API 别混**
- `update_zhcn`：会清非根语种 —— **补空禁用**
- 补空只走 `translate_row`；响应丢失后严禁误调 `update_zhcn`


## 可能追问

- 长文本怎么切？→ 按段落/句边界切块，保留占位符完整；块级校验再拼回。
- 失败队列谁消费？→ 人工或二次策略 worker；开口标明当前 vs 改进。
- 双 worker 抢同一 key？→ 当前单进程 bool；改进用幂等键 + lease（见 A04）。
