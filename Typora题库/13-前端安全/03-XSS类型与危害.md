# 题 3：XSS 有哪些类型？危害是什么？

## 面试官可能怎么问

- 反射型 / 存储型 / DOM 型？
- XSS 能干什么？
- 和 SQL 注入区别？

## 口述结构（90 秒）

1. XSS：把恶意脚本注入到受害者浏览器执行
2. 三类：反射、存储、DOM 型
3. 危害：偷 cookie/token、钓鱼、弹木马、改页面
4. 和 SQLi：一个打浏览器，一个打数据库

## 参考答案

### 1. 三类 XSS（对照例子）

| 类型 | 注入点 | 典型路径 |
| --- | --- | --- |
| 反射型 | 请求参数立刻映到页面 | 搜索词未转义直接进 HTML |
| 存储型 | 写入库/文件，他人打开即中 | 评论、昵称、工单备注 |
| DOM 型 | 不经服务端，前端 JS 把不可信输入写进 DOM | `location.hash` → `innerHTML` |

```js
// DOM 型坏例子
app.innerHTML = location.hash.slice(1) // 攻击者诱骗打开 # <img onerror=...>
```

步骤识别：看恶意脚本最终**谁写进了 HTML/JS 执行上下文**——服务端模板还是前端 DOM API。

### 2. XSS 能干什么

1. 读 `document.cookie`（若非 HttpOnly）或内存里的 token  
2. 冒充用户发请求（配合同源）  
3. 键盘记录、页面篡改、钓鱼表单  
4. 蠕虫式传播（存储型评论区）  

所以：token 放 localStorage 被 XSS 一次就可能全丢；**HttpOnly Cookie + 严格 CSP** 是后端/平台侧关键组合。

### 3. 和 SQL 注入区别

| | XSS | SQL 注入 |
| --- | --- | --- |
| 目标 | 受害者浏览器 / 前端上下文 | 数据库查询 |
| 语言 | JS/HTML | SQL |
| 防线 | 编码转义、CSP、避免危险 API | 参数化查询、权限最小化 |

面试收口：两者都是「把数据当成了代码」；场景与修复不同。

## 可能追问

- 为什么 HttpOnly 不能消灭 XSS？→ 还能改 DOM、调 API（若 cookie 自动带上则仍危险，需 CSRF 防护配合）。  
- mXSS？→ 浏览器解析差异导致的变异 XSS，富文本更常见。
